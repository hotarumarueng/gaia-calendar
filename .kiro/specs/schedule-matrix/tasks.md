# Implementation Plan — schedule-matrix

- [ ] 1. Foundation: プロジェクト基盤の構築
- [x] 1.1 Next.js プロジェクトの初期化と共有定数・型の定義
  - create-next-app（TypeScript / App Router）でプロジェクトを作成し、開発サーバーの起動を確認する
  - 固定4時間帯・曜日の定数と、共有型（時間帯ID・曜日・人単位エントリ）を定義する
  - 完了条件: `npm run dev` でトップページが表示され、定数・型が他モジュールから import できる
  - _Requirements: 6.1, 6.2_

- [ ] 1.2 DynamoDB テーブルと専用 IAM ユーザーの作成（手順書化＋手動実施）
  - テーブル定義（PK=name / SK、プロビジョンド 25RCU・25WCU）、IAM 最小権限ポリシー（対象テーブル1つ・5アクション）、AWS CLI 作成コマンドを手順書としてまとめる
  - 手順書に従い Toriumi がテーブルと IAM ユーザーを作成し、認証情報は .env.local に直接記入する（チャットには貼らない）
  - 完了条件: describe-table が ACTIVE かつ課金モード PROVISIONED を返し、.env.local に4つの環境変数が揃っている
  - _Requirements: 2.3_

- [ ] 1.3 テスト基盤の導入
  - vitest を導入し、サンプルテストで実行環境を確認する
  - 完了条件: `npm test` がサンプルテストのパスを報告する
  - _Requirements: 2.1, 2.4, 1.4_

- [ ] 2. Core: 整合性ルールとデータ層
- [ ] 2.1 (P) 整合性ルールの純粋関数と単体テスト
  - 名前検証（trim・空白のみはエラー）、時間帯ごとの希望を保存対象と削除対象へ振り分けるロジック（空配列=削除）、最終編集日時の算出（最大値・空なら null）を実装する
  - 全時間帯がちょうど1回どちらかに振り分けられる不変条件をテストで担保する
  - 完了条件: 上記3関数の単体テストが `npm test` で全て通る
  - _Requirements: 2.1, 2.4, 2.5, 1.4_
  - _Boundary: entryRules_

- [ ] 2.2 (P) 本人名のブラウザ記憶ユーティリティ
  - localStorage への名前の保存・取得（キー `gaia-calendar:name`）を実装し、サーバーサイド実行時に安全に no-op となるようにする
  - 完了条件: 保存した名前がページ再読み込み後も取得できる
  - _Requirements: 3.1_
  - _Boundary: identity_

- [ ] 2.3 DynamoDB アクセス層の実装
  - 環境変数から DocumentClient を構成し、表データ取得（Scan して人単位に組み立て、未入力時間帯は空配列で補完）、人単位保存（Member の PutItem + 時間帯ごとの PutItem/DeleteItem）、人単位削除（Query で全 item を取得して削除）を実装する
  - 書き込み時に updatedAt を必ず設定する（DB 側に default がないため）
  - 完了条件: 実テーブルに対して保存→取得→削除の一連が動作し、削除後に当該参加者の item が残らない
  - _Requirements: 2.2, 2.3, 5.1_

- [ ] 3. Core: API と UI コンポーネント
- [ ] 3.1 人単位の保存・削除 API の実装
  - POST で整合性ルールを適用（trim 後の空名前・未知の時間帯/曜日は 400）、正常時は人単位で保存する。DELETE は名前指定で人単位削除を行う。DB 障害時は 500 と再試行案内を返す
  - 完了条件: curl で 保存=200、空名前=400、削除=200 が確認できる
  - _Requirements: 2.1, 2.4, 2.5, 4.1, 4.2, 5.1_

- [ ] 3.2 (P) マトリクス表コンポーネントの実装
  - 縦=参加者名・横=固定4時間帯の表を描画し、セルに希望曜日、行にコメントと最終編集日時を表示する。参加者ゼロ時は空状態の案内を表示する
  - ブラウザに記憶された名前と一致する行にのみ編集・削除ボタンを表示する
  - 横スクロールコンテナ＋名前列の sticky 固定でスマホ幅に対応する（PC優先）
  - 完了条件: ダミーデータで表が正しく描画され、記憶名と一致する行だけに操作ボタンが出る
  - _Requirements: 1.1, 1.2, 1.3, 1.4, 1.5, 3.2, 3.3, 4.3, 6.3_
  - _Boundary: MatrixTable_
  - _Depends: 2.2_

- [ ] 3.3 入力フォームと削除確認の実装
  - 名前・コメント・4時間帯×曜日チェックの入力フォームを実装し、保存で API を呼び、成功時に名前をブラウザへ記憶して表を最新化する。400 応答はフォームにインライン表示する
  - 削除ボタンは確認を挟んでから削除 API を呼ぶ
  - 完了条件: フォーム保存で表が更新され、削除実行で行が消える
  - _Requirements: 2.1, 2.5, 3.1, 4.1, 5.1, 5.2_

  - 完了条件: URL を開くだけで実データの表と入力フォームが表示され、ログインを求められない
